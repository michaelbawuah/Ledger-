# Synthetic study workloads

The study profiles exercise different matching mechanisms with deterministic,
replayable commands. They are generated by the independent `ReferenceBook`, not
by the fast engine being measured. Generation and preload happen before any
benchmark timer starts. These are synthetic experiments; their trade reports
describe simulated matching, not orders sent to an exchange.

## Parameters and preload

`make_workload(profile, commands, seed, depth, domain)` returns a `Workload` with
two command vectors. `preload` establishes the initial book; `commands` contains
exactly the requested number of measured commands. Sequence numbers are
contiguous across both vectors. The preload contains **`depth` resting orders
per side**, each at a distinct price, for `2 * depth` initial orders and levels.
All preload orders are accepted GTC limits and none cross the spread.

| Parameter | Meaning and valid range |
| --- | --- |
| `commands` | Measured commands only, 0–1,000,000 in the C++ API; the study CLI requires at least one |
| `seed` | Unsigned 64-bit seed, including zero |
| `depth` | Initial orders and occupied price levels **per side**, 1–16,384 |
| `domain` | Positive inclusive price interval `[1, domain]`, `2 * depth`–1,000,000 |
| `max_orders` | `max(4 * depth, 1024)`, therefore 1,024–65,536 |

The capacity relation leaves space for measured replenishment while keeping
pool-size experiments tied to the requested depth. It is not the original
generator's fixed target of 2,048 live orders.

For `depth > 1`, the initial bids span price 1 through `floor(domain / 2)` and the
asks span `floor(domain / 2) + 1` through `domain`. Integer interpolation creates
distinct slots because `domain >= 2 * depth`. Wider domains therefore increase
the distances between live levels without changing initial order count. At
`depth = 1`, the two initial prices sit on either side of the midpoint. Seeded
maker quantities are 1–32 units. Replenishment uses those same per-side slots,
so new limits and ordinary replacements remain noncrossing.

## Profiles

| Profile | Commands and mechanisms |
| --- | --- |
| `balanced` | Mixed new limits, valid cancels, replacements, and fully sized 1–4-maker market/IOC sweeps. Low-side replenishment and a `3 * depth` live-order ceiling prevent depletion and capacity drift. |
| `cancel_heavy` | Valid active-ID cancellations are selected with 70% probability during a churn phase; the other commands add liquidity. At `depth` total live orders, an explicit refill phase restores `2 * depth` before churn resumes. |
| `trade_storm` | A market or crossing IOC consumes exactly 1–64 actual makers in price/FIFO order, then measured limit commands restore each side to `depth`. Sweep size is capped by real available makers for small depth values. |
| `replace_heavy` | The ordinary selection mix includes 30% replacements, 35% additions, 25% cancels, and 10% small sweeps, subject to depletion/capacity guards. Every replace uses a currently live ID and its original side; the new quantity and price vary. |
| `sparse_fok` | Successful priced FOK orders consume 1–64 makers. Shortage FOK orders admit all opposite live prices but request available quantity plus one, so rejection must examine existing dispersed liquidity. Refill selects empty slots to preserve sparse levels. |
| `rejection_stress` | About 80% intentionally rejected requests cover eight reasons; the remaining requests are valid same-side replacements that preserve initial live depth. |

The ordinary selection percentages are generation rules, not promised final
action percentages. A sweep consuming 64 makers requires 64 later single-order
adds to restore that liquidity; those additions are measured. The trade-storm
profile consequently produces trade bursts separated by visible replenishment
periods. Its 1–64 fill counts come from actual FIFO maker queues, not fabricated
diagnostic counters or requested sizes unconnected to live orders.

A sustained stream of successful cancels cannot contain 70% cancel commands
when only 30% of commands add one order each: the initial supply eventually runs
out. The cancel profile exposes that constraint through measured refill phases.
Long runs approach roughly half adds and half successful cancels; a short churn
phase can realize a higher cancel fraction by consuming preload supply. Use the
recorded action/result counts when interpreting any run. This profile never
substitutes unknown-ID rejections for active cancellations.

Sparse FOK failures always have a nonempty contra side. A buy failure uses the
domain maximum price, and a sell failure uses the domain minimum. Their request
is one unit larger than the sum of **all** existing opposite maker quantities.
The successful requests choose a limit admitting the actual final maker in
their selected FIFO sweep. Both branches use real liquidity; empty-book
shortcuts are excluded. Success versus shortage selection is equiprobable when
the sides have been replenished, but refill commands reduce both branches'
fraction of total measured commands.

The rejection profile explicitly creates `UnknownId`, `DuplicateId`,
`InvalidPrice`, `InvalidQuantity`, `InvalidId`, `WrongSide`, `InvalidCommand`
(invalid time-in-force value), and `WouldNotFill`. It does not claim capacity
rejections: no profile silently relies on an undersized order pool to keep its
size bounded. Rejected FOK requests preserve the full resting book.

## Reproducibility and verification

The random source is specified SplitMix64 integer arithmetic with rejection
sampling for bounded draws. No standard-library random distribution participates
in command selection, so identical parameters produce identical command fields
on supported compilers. The seed changes maker quantities and measured command
selection. Prices and quantities use integer ticks and units throughout.

During generation, an event-updated live-ID index tracks side, price, remaining
quantity, and FIFO position independently of the reference book's own storage.
Every command is checked for its intended applied/rejected outcome. After every
command, live-order count, total resting quantity, and capacity agree. Full
reference invariants, all resting order fields, complete FIFO order, and side
lookup positions are checked after preload, every 4,096 measured commands, and
at completion. These checks are outside benchmark timing.

`study_workload_tests.cpp` additionally replays all six profiles through the
independent reference and both fast price-search modes, comparing every emitted
event and final full snapshots. Tests exercise seed changes, repeated seeds,
the smallest valid price domain/depth, maximum pool depth, wide domains,
malformed parameters, realized profile mechanisms, all eight rejection reasons,
and the full observed 1–64-maker sweep range for a fixed deterministic run.
